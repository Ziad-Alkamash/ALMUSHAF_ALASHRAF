# خادم إشعارات الدفع — المصحف الأشرف (للراسبيري باي)

خادم صغير جدًا (Node.js + Express) مهمته إرسال إشعارات push حقيقية تصل حتى
بعد إغلاق تطبيق المصحف الأشرف تمامًا. مصمَّم عمدًا ليكون **خفيفًا**:

- لا قاعدة بيانات — ملف JSON صغير واحد فقط (`data/subscribers.json`).
- المُجدوِل الذي يعمل كل دقيقة لا يفعل شيئًا سوى مقارنة نصوص أوقات بسيطة في
  الذاكرة — لا استعلامات، لا معالجة صور، لا شيء ثقيل.
- طلبات الشبكة الفعلية قليلة جدًا: مرة واحدة يوميًا فقط لكل مشترك لجلب
  مواقيت الصلاة، ومرة كل 4 ساعات لإرسال دعاء الفقيد. هذا لن يُحسّ بجانب باقي
  خدماتك على الجهاز.

## 1) المتطلبات

- Raspberry Pi يعمل عليه Node.js 18 أو أحدث (`node -v` للتأكد).
- إذا لم يكن مثبّتًا: `curl -fsSL https://deb.nodesource.com/setup_lts.x | sudo -E bash - && sudo apt install -y nodejs`

## 2) التثبيت

```bash
cd push-server
npm install
```

## 3) توليد مفاتيح VAPID (مرة واحدة فقط)

```bash
npm run generate-vapid
```

انسخ الناتج، ثم:

```bash
cp .env.example .env
nano .env   # الصق VAPID_PUBLIC_KEY و VAPID_PRIVATE_KEY هنا
```

اضبط أيضًا `TZ` على منطقتك الزمنية (مثال: `Africa/Cairo`) حتى تكون مواعيد
التذكيرات (٦ مساءً، ١٠ مساءً...) صحيحة.

## 4) التشغيل

```bash
npm start
```

للتأكد أنه يعمل بشكل دائم ويُعاد تشغيله تلقائيًا بعد إعادة تشغيل الجهاز أو
انقطاع الكهرباء (وهو خفيف جدًا فلن يُثقل على أي خدمة أخرى تُدار بـ pm2):

```bash
sudo npm install -g pm2
pm2 start server.js --name mushaf-push
pm2 save
pm2 startup   # نفّذ الأمر الذي يطبعه لك لتفعيل التشغيل التلقائي عند الإقلاع
```

## 5) جعل السيرفر متاحًا للتطبيق عبر HTTPS

المتصفح يمنع صفحة PWA تعمل على HTTPS من مناداة سيرفر HTTP عادي (Mixed
Content)، لذلك يحتاج هذا السيرفر رابطًا بـ HTTPS يصل إليه من الخارج، **بدون**
فتح أي منفذ على الراوتر وبدون أي حمل يُذكر على الراسبيري باي — أسهل طريقة هي
نفق Cloudflare المجاني (`cloudflared`)، وهو اتصال صادر فقط (Outbound) فلا يحتاج
Port Forwarding ولا يُبقي أي منفذ مفتوحًا على شبكتك:

```bash
# تثبيت cloudflared على الراسبيري باي (ARM)
curl -L --output cloudflared.deb https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-arm64.deb
sudo dpkg -i cloudflared.deb

# نفق سريع للتجربة فورًا (يعطيك رابطًا عشوائيًا من trycloudflare.com، صالح طالما الأمر شغّال)
cloudflared tunnel --url http://localhost:8787
```

سيطبع لك رابطًا مثل `https://random-name.trycloudflare.com` — هذا هو
`serverUrl`. لرابط ثابت دائم (يُنصح به بعد التأكد أن كل شيء يعمل)، اربط نفقًا
مُسمّى بدومين تملكه عبر لوحة Cloudflare (خطوات "Named Tunnels" في توثيق
Cloudflare)، ثم شغّله كخدمة دائمة بنفس طريقة pm2 أعلاه، أو كخدمة systemd.

> بديل: إذا كان لديك بالفعل دومين وشهادة HTTPS (Let's Encrypt) على السيرفر
> نفسه أو عبر Nginx كـ reverse proxy أمام المنفذ 8787، يمكنك استخدامه بدل
> Cloudflare Tunnel مباشرة.

## 6) ربط التطبيق بالسيرفر

افتح ملف `app.js` (في مجلد التطبيق الرئيسي، ليس هذا المجلد) وعدّل أعلى الملف:

```js
const PUSH_CONFIG = {
  serverUrl: 'https://your-tunnel-or-domain.example.com',
  vapidPublicKey: 'BN4Gv...' // نفس VAPID_PUBLIC_KEY من .env
};
```

ثم أعد رفع/نشر ملف `app.js` المُحدَّث إلى مكان استضافة التطبيق. من هذه اللحظة،
عند ضغط المستخدم زر "تفعيل" الإشعارات داخل التطبيق، سيُسجَّل اشتراكه تلقائيًا
في هذا السيرفر، وأي تغيير لاحق في مواعيد التذكيرات يُرسَل تلقائيًا أيضًا.

## البيانات المخزَّنة

ملف `data/subscribers.json` يحتوي على اشتراكات الدفع (لا تحتوي على أي معلومات
شخصية عدا الموقع الجغرافي التقريبي المستخدم فقط لحساب مواقيت الصلاة). احتفظ
بنسخة احتياطية منه إذا أعدت تهيئة الجهاز.

## استكشاف الأخطاء

- **لا تصل الإشعارات أبدًا**: تأكد أن `serverUrl` بروتوكوله `https://` فعليًا
  يفتح ويستجيب لـ `GET /health`، وأن المتصفح أعطى إذن الإشعارات فعلاً.
- **الإشعارات تتوقف فجأة لمستخدم واحد فقط**: على الأرجح انتهت صلاحية اشتراكه
  (يحصل أحيانًا إذا لم يفتح المتصفح لفترة طويلة) — السيرفر يحذفه تلقائيًا من
  `subscribers.json` عند اكتشاف ذلك (رد 404/410)، وسيُعاد تسجيله تلقائيًا في
  المرة القادمة التي يفتح فيها التطبيق.
- **مواقيت الصلاة غير صحيحة**: تأكد أن السيرفر يملك صلاحية الوصول للإنترنت
  للاتصال بـ `api.aladhan.com`، وأن إحداثيات الموقع وصلت (تحتاج المستخدم أن
  يسمح بالوصول لموقعه الجغرافي في التطبيق أولاً).
